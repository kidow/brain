# notes 낭독 오디오 계획

> **이 문서는 `notes/` 한 편을 통째로 읽어 주는 5~15분짜리 낭독 오디오에 대한 것이다.**
> `vocab/` 단어 하나짜리 발음 mp3는 [audio/PLAN.md](../audio/PLAN.md)에 따로 있다.
> 둘은 TTS 엔진(Grok)만 공유하고 저장 위치·길이·용도가 전부 다르다.

| | `audio/` | `_notes_audio/` (여기) |
|---|---|---|
| 대상 | `vocab/` 단어 2,827개 | `notes/` 239편 |
| 길이 | 개당 0.4~1.2초 | 편당 5~15분 |
| 저장 | 저장소 커밋 (약 9MB) | Vercel Blob (약 450MB) |
| 이 폴더에 든 것 | mp3 실물 (서빙됨) | 대본 텍스트와 계획 (`_` 접두사라 빌드 제외) |
| 스크립트 | `scripts/build_vocab_audio.py` | `scripts/split_audio_script.py` |

이동 시간에 이어폰으로 notes를 듣기 위한 설계.

## 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 소비 경로 | 노트 페이지 `<audio>` 재생기 **only** (팟캐스트 RSS 없음) | LTE로 스트리밍하면 지하철에서도 문제없음. 데이터는 시간당 약 14MB |
| 재생기 기능 | 자동 연속재생 + 이어듣기 + 잠금화면 컨트롤 | 이 셋이 없으면 6분마다 폰을 꺼내야 해서 출퇴근 청취가 성립하지 않음 |
| 연속재생 범위 | `_data/notes_order.yml` **그룹 안에서만**, 끝나면 정지 | 기존 페이지네이션 규칙과 동일. 러시아어 듣다 회계학으로 넘어가지 않음 |
| 대상 | `notes/` 239개만 | sheets는 표 위주라 낭독에 부적합하고 내용도 notes와 겹침. drills는 포맷이 완전히 다른 별개 제품 |
| 대본 생성 | LLM 재작성 (기계 변환 아님) | 표·별표·샤프를 그대로 읽으면 못 들음. 자연스러운 톤이 목표 |
| 대본 실행 | **Claude Code 서브에이전트** (프롬프트: [prompt.md](prompt.md)) | 로컬 4bit 모델은 한국어 표 풀어쓰기 품질이 미검증이고 스파이크 비용이 먼저 든다. 표·예문 블록 변환은 판단이 섞여 품질이 곧 산출물이다 |
| 대본 성격 | 원문 충실 낭독본 (요약 아님) | 프롬프트가 '변환'만 시키므로 환각·누락 위험이 가장 낮다. 대신 전체 50시간+ |
| 외국어 원어 | 원어 문자 그대로, 음차 금지 | 음차는 날조다(`vocab/` 규칙과 같은 이유). 발음이 살아야 어학 복습으로 의미가 있다 |
| 예문 낭독 순서 | 원어 → 뜻 | 수동 청취에 맞다. 프롬프트가 '왼쪽→오른쪽' 기계 규칙이라 지키기 쉽다 |
| 나레이션 | 제목 + 헤딩만, 전환·마무리 멘트 없음 | 대본이 원문과 1:1로 대응해 누락 검사가 가능해진다 |
| 대본 출력 | 순수 텍스트 + 빈 줄 문단. 청크 분할은 스크립트 | LLM에 길이를 세게 하면 틀린다. 문단 경계에서 잘라 ffmpeg으로 잇는다 |
| 대본 검증 | 기계 검사 스크립트 (239개 전수) | 사람이 다 못 듣는다. 헤딩 수·외국어 토큰 포함·길이 비율 셋으로 거른다 |
| 대본 저장 | `_audio/scripts/<노트경로>.txt`, **git 커밋** | 로컬 LLM은 출력이 매번 달라서 이게 유일한 재현 수단. 텍스트라 전체 1MB 안팎 |
| mp3 호스팅 | **Vercel Blob** (2026-08-07 변경) | DNS를 안 건드린다. 아래 "R2를 접은 이유" 참고 |
| 첫 실행 | Languages — Russian 22개 파일럿 | 파이프라인 전체를 짧게 검증한 뒤 나머지 217개 확장 |

## 스파이크 결과 — Grok TTS로 확정 (2026-08-07)

물어본 것은 하나였다. **한국어 문장 한가운데 박힌 키릴·한자를 코드스위칭해서 읽는가.**
안 되면 낭독본 자체가 성립하지 않으므로 대본을 더 만들기 전에 확인해야 했다.

노트 3개(어학 표 위주 1 + 산문 1 + 예문 블록 위주 1)로 대본을 만들어 던졌다.
러시아어 동사상 5분 57초, 주식 용어 7분 53초를 받아 **사람이 들어 확인했다 — 원어로 읽는다.**
중국어 회화는 길이 때문에 실패했고, 이건 언어 문제가 아니라 입력 한계였다(아래).

Chatterbox Multilingual V3, mlx-audio + Qwen3-TTS는 대안으로 적어 뒀던 것인데
쓰지 않는다. `vocab/`이 이미 같은 엔진을 쓰고 있어 파이프라인이 하나로 붙는다.

## 파이프라인

```
notes/**/*.md (239개)
  ↓ ① Claude Code 재작성 (_audio/prompt.md)
_audio/scripts/**/*.txt   ← git 커밋, 상단에 원문 md의 sha256 기록
  ↓ ② TTS
  ↓ ③ ffmpeg 인코딩 (32kbps 모노)
*.mp3 (약 450MB)
  ↓ ④ vercel blob put
https://<store>.public.blob.vercel-storage.com/notes/<그룹>/<파일명>.mp3
  ↓ ⑤ _layouts/note.html이 page.path로 URL 계산
브라우저 재생기
```

### 증분 빌드

대본 파일 상단에 원문 md의 sha256을 기록한다. 빌드 시 현재 md 해시와 비교해 **다른 노트만** ①~④를 다시 돌린다. 노트 하나 고쳤을 때 전체 5시간을 다시 돌리지 않기 위한 장치이며, 없으면 파이프라인이 사실상 일회용이 된다.

### TTS 입력 한계 — 청크로 쪼갠다 (2026-08-07 실측)

Grok TTS는 대본 하나를 통째로 못 받는다. 스파이크에서 걸렸다.

```
2,891자 (러시아어 동사상)  통과 · 5분 57초
3,577자 (주식 용어)        통과 · 7분 53초
6,736자 (중국어 회화)      실패
```

진짜 한계는 3,577~6,736 사이다. 좁히지 않았다 — [scripts/split_audio_script.py](../scripts/split_audio_script.py)의
`DEFAULT_LIMIT`을 통과 실적 바로 위인 **3,600자**로 두고 넘는 대본만 쪼갠다.
이분 탐색으로 좁히면 `--limit`으로 올려 생성 횟수를 줄일 수 있다.

**자르는 곳은 빈 줄(문단 경계)뿐이다.** 문장 중간에서 끊으면 억양이 깨진다. 문단 하나가
한계를 넘으면 줄 단위로 내려가고, 줄 하나가 넘으면 멈춘다 — 조용히 뭉개지 않는다.
조각 수를 늘리지 않는 선에서 길이를 고르게 편다(6,736자 → 3,379 + 3,354, 각 7분대).

```bash
python3 scripts/split_audio_script.py --check            # 전체 대본 현황
python3 scripts/split_audio_script.py <대본.txt>          # 넘으면 .partN.txt 로 쪼갬
ffmpeg -f concat -safe 0 -i parts.txt -c copy 합본.mp3    # 받은 뒤 잇기
```

**글자 수는 파이썬 `len()` 기준이다.** `wc -m`은 로케일에 따라 바이트를 세서 한국어를
2~3배로 부풀린다. 처음 이 값으로 한계를 잡았다가 틀린 기준을 세울 뻔했다.

### 예상 소요 (2026-08-07 실측 기반)

- 원문 861,247자 / 노트 239개 (파이썬 `len()`. 이전 문서의 852,922자·평균 3,569자는 집계 기준이 달랐다)
- 대본은 원문의 약 1.0배. 표를 문장으로 풀면 늘고(주식 1.19배), 병음 열을 걷어내면 준다(중국어 0.82배)
- 낭독 속도 **7.8자/초** 실측 → 전체 약 **31시간**
- mp3 용량: 32kbps 모노 기준 약 **450MB**
- TTS 생성 횟수: 3,600자 청크 기준 약 **245회**

## 구현 순서

1. ~~**스파이크**~~ — 완료 (2026-08-07). 코드스위칭 발음 확인, 프롬프트 확정,
   TTS 입력 한계 발견 후 분할기 추가. 결과는 위 두 절에 있다
2. **Blob 셋업** — `vercel login` → `vercel blob create-store brain-audio --access public`.
   대시보드에서 무료 한도(저장 용량·전송량)를 먼저 본다
3. **빌드 스크립트** (`scripts/build_audio.py`) — 대본 생성 → TTS → ffmpeg → `vercel blob put`. 해시 기반 증분 처리
4. **재생기** (`_layouts/note.html` + `assets/js/audio-player.js`) — md 239개는 건드리지 않는다
   - `<h1>brain</h1>` 바로 아래에 `<audio>` 블록 삽입 (레이아웃 1곳만 수정)
   - 곡 종료 시 `_data/notes_order.yml` 기준 같은 그룹의 다음 노트 mp3로 `src` 교체 (페이지 이동 없음)
   - localStorage에 재생 위치 저장 — 노트 경로별로 `{ path, time }`을 넣고 `pagehide`에서 쓰기, 스크롤처럼 잦은 이벤트는 300ms 스로틀
   - MediaSession API로 잠금화면에 제목·이전/다음 노출
5. **파일럿** — Languages — Russian 22개 생성·업로드, 실제 출퇴근에 청취
6. **전체 확장** — 나머지 217개

## R2를 접은 이유 (2026-08-07)

계획에 "partial(CNAME) 셋업이면 네임서버 이전 불필요"라고 적어 뒀는데, **무료 플랜에는
그 선택지가 없다.** Cloudflare에 도메인을 넣으면 네임서버를 통째로 옮기는 전체 설정만 뜬다.

옮기려다 더 큰 걸 봤다 — **Cloudflare 스캔이 `brain` CNAME을 놓쳤다.**

```
실제:  brain.dongwook.kim  CNAME  kidow.github.io
스캔:  없음 (CNAME은 _domainconnect 하나뿐)
```

그 상태로 활성화했으면 와일드카드 `* → 64.29.17.1`(Vercel)이 대신 잡혀 이 사이트가
통째로 엉뚱한 곳을 가리켰을 것이다. 메일(daum MX)도 같은 DNS에 걸려 있다.

450MB 하나 올리자고 도메인 전체의 DNS 주체를 바꿀 일이 아니다. 도메인이 이미 Vercel에
있고 네임서버도 `ns1/ns2.vercel-dns.com`이므로, Vercel Blob을 쓰면 DNS를 아예 안 건드린다.

## 검증하지 못한 것

- **토큰 수 추정치**: 이 환경에 `ANTHROPIC_API_KEY`도 `ant` CLI도 없어 `count_tokens`를 실행하지 못했다. 852,922자 → 50~70만 토큰은 한국어 토큰 밀도 가정에 기반한 추정
- **TTS·LLM 품질**: 저장소 문서와 벤치마크 기준이며 실제로 들어본 결과가 아니다. 스파이크에서 확인
- **한국어 특화 모델의 MLX 변환본 존재 여부**
