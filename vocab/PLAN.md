# 8언어 대조 단어장 (vocab/) 계획서

카테고리(색깔·동물·숫자…)별로 8개 언어의 대응어를 한 화면에서 대조하는 단어장.
기존 `drills/`가 언어별 세로축이라면, 이쪽은 **개념별 횡단면**이다.

대상 언어 8개, 표시 순서 고정: **영 · 일 · 중 · 프 · 독 · 스 · 러 · 아**

---

## 1. 페이지 구조

- 카테고리당 페이지 1개: `vocab/색깔.html` + `vocab/색깔.json`
- 페이지 상단에 카테고리 네비게이션 — 서로 이동. **미완성 카테고리는 숨김**(비활성 표시 아님)
- 렌더러는 공유: `assets/js/vocab.js` 1벌. HTML은 껍데기(~40줄)
  - `drills/`는 19개 파일이 각자 인라인 `<script>`를 복제하고 있으나, 이 패턴은 따르지 않는다

### 개념 펼침 UI (반응형 2모드)

| 뷰 | 모드 |
|---|---|
| 데스크탑 | **마스터–디테일** — 왼쪽 개념 목록 고정, 오른쪽 패널 교체 |
| 모바일 | **아코디언** — 개념 줄 클릭 시 그 자리에서 펼침 |

`matchMedia`로 모드 전환. 두 모드는 DOM 구조가 달라 JSON → JS 렌더 방식이 된다.

### 언어 한 줄의 구성

`원어` + `현지 표기/로마자`(かな · 병음 · 라틴 전사 · IPA) + `한글 음차`

- **아랍어는 음차 생략** — 국립국어원 외래어 표기법에 아랍어 세칙이 없다
- **프랑스어·스페인어는 `rom` 생략** — 위키낱말사전이 이 둘의 발음을 템플릿(`{{es-pr}}` 등)으로
  자동 생성해 원문에서 IPA를 못 긁는다. 지어내지 않기 위해 비우고 한글 음차가 발음을 담당한다.
  영어·독일어는 원문에 IPA가 그대로 있어 수록한다 (11/11 확보)
- 문법 정보(성·활용)는 넣지 않는다 → `notes/` 담당

### 1:1로 안 맞을 때

- `alt[]` — 해당 언어 줄 안에 보조어를 들여쓰기 + 라벨로 병기
  (러 `синий`(짙은)/`голубой`(옅은), 아 `أزرق`(남)/`زرقاء`(여))
- `notes[]` — **필요한 개념에만** 카드 하단 메모
  (일본어 `青`가 초록까지 덮는 배경 등)

## 2. 출처 정책 (2층)

| 층 | 역할 | 출처 |
|---|---|---|
| 개념 선정 | 무슨 개념을 넣을지 | Swadesh 207 / Berlin & Kay(1969) 등 표준 목록 |
| 단어 | 각 언어에서 뭐라 하는지 | Wiktionary (언어별 Swadesh 부록 + 표제어) |

`lists[]` 필드로 개념마다 근거 목록을 기록 → "코어만 보기" 필터가 공짜로 생긴다.

### 확인된 사실 (2026-08-06)

- Wiktionary에 8개 언어 Swadesh 부록이 **전부 존재**. 로마자 병기 포함
- IDS(ids.clld.org)는 웹 표가 JS 렌더라 `/chapters`·`/contributions` 모두 빈 테이블로 내려온다
  → **카테고리 이름 참고용으로만** 쓰고 데이터 원본에서 제외 (CLDF 파싱은 이 규모에 과함)

### 알려진 한계 — 반드시 페이지 하단에 명시

**한글 음차는 개별 단어의 출처가 없다.** 국립국어원 외래어 표기법 규정을 적용한 결과이지
용례집 등재 표기가 아닌 경우가 대부분이다(`чёрный` → `초르니`).
원어·전사는 Wiktionary 근거가 있으나 음차는 **규칙 적용값**임을 밝힌다.

## 3. 카테고리

초안 10개, 배움의 흐름 순:

`숫자` `색깔` `동물` `신체` `가족` `음식` `자연` `시간` `동작` `기본 형용사`

### 첫 타자: 색깔

**Berlin & Kay(1969) 기본색채어 11개**, 진화 단계 순으로 정렬:

```
white · black → red → green · yellow → blue → brown → purple · pink · orange · grey
```

- Swadesh 207의 색은 `black white red green yellow` 5개뿐 — 파란색이 없어 러시아어 분화 사례가 통째로 빠진다
- 러시아어는 파랑에 기본색채어가 둘이라 Berlin & Kay 연구에서 가장 유명한 예외다 → 이 카테고리의 핵심 사례

## 4. 데이터 스키마

```json
{
  "category": "색깔",
  "languages": ["en", "ja", "zh", "fr", "de", "es", "ru", "ar"],
  "sources": {
    "concepts": "Berlin & Kay (1969), Basic Color Terms",
    "words": "Wiktionary"
  },
  "concepts": [
    {
      "id": "black",
      "ko": "검은색",
      "swatch": "#000000",
      "lists": ["swadesh", "berlin-kay"],
      "words": {
        "en": { "word": "black", "rom": "/blæk/", "kor": "블랙" },
        "ja": { "word": "黒い", "rom": "くろい · kuroi", "kor": "구로이",
                "alt": [{ "word": "黒", "rom": "くろ · kuro", "kor": "구로", "label": "명사형" }] },
        "ru": { "word": "чёрный", "rom": "chyórnyy", "kor": "초르니", "label": "남성형" },
        "ar": { "word": "أسود", "rom": "aswad",
                "alt": [{ "word": "سوداء", "rom": "sawdāʾ", "label": "여성형" }] }
      },
      "notes": ["아랍어 색채 형용사는 성에 따라 형태가 바뀐다"]
    }
  ]
}
```

- `id`는 **영어 슬러그** — URL 앵커(`vocab/색깔.html#black`)가 되고 Swadesh·Berlin & Kay 목록과 1:1로 붙는다
- 파일명은 기존 규약대로 한국어 (`색깔.html`)
- `kor`는 아랍어에서 필드 자체를 생략
- `swatch`는 색깔 카테고리 전용 선택 필드

## 6. 작업 단계

천천히, 3단계로 쪼갠다. 각 단계가 독립 커밋.

### 1단계 — 데이터만
`vocab/색깔.json` 작성. 11개념 × 8언어 = **88항목**을 Wiktionary로 확인.
렌더러 없이 JSON만 놓고 눈으로 검수한다.
> 이 작업의 8할이 여기다. 렌더러를 같이 만들면 "화면이 뜬다"에 만족해 데이터 오류를 넘긴다.

### 2단계 — 렌더러
`assets/js/vocab.js` + `vocab/색깔.html`. 브라우저에서 데스크탑/모바일 두 모드 확인.

### 3단계 — 통합
README 2곳 + `Repository layout` + CLAUDE.md 규칙 + search 연동.

### 이후
카테고리를 하나씩 추가. 매번 README 두 파일 동기화 (CLAUDE.md CRITICAL 규칙).

### 진행 상황 (초안 10개 카테고리 완료)

| 카테고리 | 개념 | 항목 | 개념 목록 출처 |
|---|---:|---:|---|
| 숫자 | 13 | 104 | 기수 0~10·100·1000 (1~5는 Swadesh) |
| 색깔 | 11 | 88 | Berlin & Kay(1969) 기본색채어 |
| 동물 | 17 | 136 | Ogden 동물 + Swadesh louse |
| 신체 | 33 | 264 | Ogden 신체 + Swadesh liver |
| 가족 | 13 | 104 | Ogden 친족 + Swadesh husband·wife·child |
| 음식 | 25 | 200 | Ogden 음식 (fish·plant·seed 제외) |
| 자연 | 39 | 312 | Ogden 자연 + Swadesh ash·bark·fog·forest·lake |
| 시간 | 20 | 160 | Ogden 시간 (형용사·동사 제외) |
| 동작 | 63 | 504 | Swadesh 동사 + Ogden 동사 7개 |
| 기본 형용사 | 35 | 280 | Swadesh 형용사 30 + 수량 표현 5 |
| 스포츠 | 30 | 240 | HSK·JLPT 초급 교육과정 + 종목명 직접 선정 |
| **합계** | **299** | **2,392** | |

스포츠는 표준 목록(Swadesh·Berlin & Kay·Ogden)에 종목명이 하나도 없어 근거를 바꿨다 —
코어는 표준화된 초급 교육과정(HSK·JLPT), 종목명은 "한국에서 일상적으로 즐기는 것"을
기준으로 직접 선정하고 그 사실을 `sources.concepts`에 적었다.

카테고리 경계는 겹치지 않게 규칙으로 정리했고, 각 JSON의 `sources.concepts`에 그 규칙을 적어 두었다.
예: `fish`는 동물에만, `water`·`salt`는 음식에만, `cold`·`heat`는 기본 형용사에만 둔다.
